# 📊 Форматы обмена данными: Исследование POX, SOAP и REST

Данный репозиторий содержит лабораторную работу на тему **«Форматы обмена данными»**. 


Цель работы — освоить основные архитектурные подходы разработки веб-сервисов и провести их сравнительный анализ.

## 🎯 Предметная область
В качестве бизнес-домена выбрана система **«Бронирование отелей»**. 
Сервис оперирует следующими сущностями:
*   🏙 **Город** (City)
*   🏨 **Отель** (Hotel)
*   🚪 **Номер** (Room)
*   📅 **Бронирование** (Booking)

## 🏗 Архитектура решения
Проект спроектирован по принципу разделения ответственности (Separation of Concerns). Бизнес-логика и валидация данных полностью изолированы от слоя передачи данных.

*   **Ядро:** Единый сервисный слой (businessLogic.js) и база данных (SQLite).
*   **Адаптеры (Interfaces):** Три независимых контроллера, которые принимают запросы в разных форматах, десериализуют их и вызывают методы ядра.
    *   `POX` (Plain Old XML) — передача сырого XML через HTTP POST.
    *   `SOAP` — строгий обмен данными через XML-конверты (`<Envelope>`).
    *   `REST` — современный подход на основе ресурсов, HTTP-методов и формата JSON.

### 💡 Ключевые выводы
1.  **SOAP** — самый тяжелый формат. Из-за обязательного использования конвертов `<soap:Envelope>` и пространств имен размер пакетов в 3-4 раза превышает REST.
2.  **REST (JSON)** — самый легкий и эффективный. Использование query-параметров для GET и DELETE позволяет свести размер тела запроса к 0 байт. JSON-ответы лаконичнее XML.
3.  **POX** — занимает промежуточное положение. Легче SOAP, но проигрывает REST по компактности.
4.  **Единая логика** — доказано, что при использовании любых интерфейсов запросы обрабатываются одним и тем же методом бизнес-логики, а формат данных влияет исключительно на сетевую нагрузку.
